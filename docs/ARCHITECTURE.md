# Архитектура

## Принципиальное разделение

Мозг Толика — настоящая нейросетевая модель. Игровой код не должен подменять его решения большим деревом `if/else`. При этом модель не исполняет произвольный Lua/Python и не управляет движком напрямую.

### Слои

1. **Сбор наблюдения (Lua, серверная сторона).** Факты, которые действительно доступны NPC: собственное состояние, игрок, видимые/обнаруженные сущности, расстояния, опасные события, последние результаты действий и состояние навигации.
2. **AI-мост (Python, локальный HTTP).** Принимает версионированный JSON, вызывает модель, проверяет структуру ответа и возвращает только допустимое намерение. Мост не имеет доступа к файловой системе Garry's Mod и не может выполнять игровые действия.
3. **Модель (первый адаптер — Ollama).** Выбирает высокоуровневое намерение по структурированному наблюдению. Выбор модели является экспериментальным: задержка и качество должны быть измерены до подключения к игровому циклу.
4. **Валидатор намерения (Lua).** Проверяет формат, актуальность ответа, допустимость действия и то, что исходное состояние не изменилось настолько, что ответ устарел.
5. **Исполнитель действий (Lua).** Использует API игры для навигации и других разрешённых действий. Ошибки исполнения и результат возвращаются в следующий снимок наблюдения.
6. **Память.** Временный контекст используется для текущей ситуации. Долговременный профиль хранит только отобранный опыт и тенденции поведения; это отдельная подсистема с собственным форматом и правилами сброса.

## Поток данных

```text
Garry's Mod (server)
  -> Snapshot of world and NPC state
  -> Python bridge (127.0.0.1)
  -> local neural model through Ollama
  <- JSON decision (schema-validated)
  -> Lua validates freshness and allowed intent
  -> game action executor
  -> observed result becomes feedback
```

Вызов модели никогда не должен блокировать игровой поток. Решения запрашиваются асинхронно и с ограниченной частотой. Если приходит запоздалый ответ, он отбрасывается, когда контекст уже изменился.

## Уникальность NPC

Единственный активный экземпляр контролируется на сервере. Spawn Menu — лишь интерфейс создания, а не механизм защиты от дубликатов. При удалении сущности ссылка на активный экземпляр очищается. Жизненный цикл при смерти, перерождении и смене карты должен быть отдельно проверен.

## Модель игрока

Отношение к игроку нельзя сводить к одному числу «послушания». В долгосрочном профиле должны быть различимы:
- доверие и стремление оставаться рядом;
- действия игрока, которые NPC пытается перенять;
- воспринимаемый авторитет наставника/командира;
- оценка того, какие действия безопасны для NPC с его собственными возможностями.

Понимание того, что игрок возвращается после смерти, должно опираться на реальные игровые события и повторяющиеся наблюдения. Нельзя делать вывод об этом из одной случайной ситуации.

## Боль, риск и окончание жизни

Нужно отдельно представлять:
- замеченный урон и его последствия;
- текущую оценку опасности;
- вероятность потерять текущую жизнь;
- завершение текущей жизни как отдельное игровое событие.

Система не должна говорить модели, что она уже пережила собственную смерть, а потом ожидать, что она это забудет. Политика памяти должна предотвращать сохранение такого факта с самого начала.

## Две памяти, два жизненных цикла

**Краткосрочная память** содержит недавние события текущей жизни и сбрасывается при её окончании.

**Долговременная память** хранит отобранные навыки, привычки и обобщения опыта. Она переживает появление нового экземпляра NPC, но не содержит истории его собственных смертей. Сам факт сброса краткосрочного контекста не должен сохраняться как запись «я умер».

Это не равнозначно автоматическому изменению весов нейросети. Первая версия обучения может обновлять структурированный профиль и примеры поведения. Дообучение параметров модели потребует отдельного эксперимента и измерения риска деградации.

## Отказоустойчивость и безопасность

- AI-мост слушает только loopback по умолчанию.
- Сервер Garry's Mod является источником истины о состоянии мира.
- Ответ модели — данные, не код и не команда оболочки.
- Структура, диапазоны и список намерений проверяются до исполнения.
- У запроса есть тайм-аут; повторные запросы ограничены.
- Если модель недоступна, NPC сообщает о состоянии через журнал диагностики; это не должно маскироваться под автономное нейросетевое решение.
- Секреты, облачные токены и персональные данные не нужны первому локальному прототипу.
