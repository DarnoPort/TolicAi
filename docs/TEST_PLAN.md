# План проверок

## Автономные тесты

Из корня репозитория:

```sh
python -m unittest discover -s tests -v
```

Эти тесты проверяют только валидацию протокола. Они не требуют запуска Ollama.

## Проверка AI-моста

1. Убедитесь, что Ollama запущена и выбранная модель установлена.
2. Запустите `python ai_service/server.py`.
3. Откройте `http://127.0.0.1:8765/health`.
4. Убедитесь, что `ollama_reachable` и `model_available` имеют значение `true`.
5. Отправьте POST /api/decision с примером из [AI_PROTOCOL.md](AI_PROTOCOL.md).
6. Повторите проверку при остановленной Ollama и с неверным JSON. Мост должен вернуть понятную ошибку, а не завершиться аварийно.

## Последний подтверждённый запуск

2026-10-21 автор выполнил `tolic_ai_test_decision` и получил:

```text
[Tolic AI] Sending a diagnostic observation to the neural model...
[Tolic AI] Model: qwen2.5:3b; intent: assist_player; risk: moderate; confidence: 0.75; summary: Assist player
```

Это подтверждает один успешный диагностический обмен с моделью. Это не проверка длительной стабильности и не означает, что NPC уже исполняет выбранные намерения.

## Проверка в Garry's Mod

1. Установите каталог аддона в `garrysmod/addons/tolic_ai/`.
2. Запустите игру и посмотрите серверную консоль на сообщения `[Tolic AI]`.
3. Выполните `tolic_ai_bridge_status`.
4. Выполните `tolic_ai_test_decision`. Успех означает только, что реальная модель ответила на тестовое наблюдение; это ещё не означает, что NPC управляется моделью.
5. Создайте **Adaptive NPC (Prototype)**.
6. Попробуйте создать второй экземпляр. Второй не должен оставаться в мире.
7. Удалите NPC и создайте его снова. Активная ссылка должна восстановиться.

## Что ещё не проверено

Диагностическая команда уже запускалась и вернула ответ модели, однако жизненный цикл NPC (создание/удаление/смерть/повторное создание), вывод Spawn Menu, исполнение игровых действий, поведение при сбое моста и производительность остаются непроверенными.
