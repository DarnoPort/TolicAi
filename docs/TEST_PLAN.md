# План проверок

## Автономные тесты

Из корня репозитория:

```sh
python -m unittest discover -s tests -v
```

Тесты проверяют валидацию протокола и HTTP-обработчик: успех, неверный JSON, недоступную модель, некорректный ответ модели и ответ health при остановленной Ollama. Запросы к модели в этих тестах подменяются, поэтому настоящая Ollama не запускается.

## Проверка AI-моста

1. Убедитесь, что Ollama запущена и выбранная модель установлена.
2. Запустите `python ai_service/server.py`.
3. Откройте `http://127.0.0.1:8765/health`.
4. Убедитесь, что `ollama_reachable` и `model_available` имеют значение `true`.
5. Отправьте POST /api/decision с примером из [AI_PROTOCOL.md](AI_PROTOCOL.md).
6. Повторите проверку при остановленной Ollama и с неверным JSON. Мост должен вернуть понятную ошибку, а не завершиться аварийно.

## Ручная проверка холодного и прогретого запуска

1. Обновите репозиторий до текущего `main`.
2. Остановите старый Python-мост сочетанием `Ctrl+C` в его окне.
3. В новом окне CMD выполните:
   ```bat
   cd /d D:\TolicAi
   set TOLIC_MODEL_TIMEOUT=180
   py -3 ai_service\\server.py
   ```
4. Перезапустите выделенный сервер Garry's Mod, чтобы загрузилась новая Lua-настройка `RequestTimeout = 190`.
5. Перезапустите Ollama и не прогревайте модель вручную перед первой проверкой. В серверной консоли Garry's Mod запустите `tolic_ai_test_decision` и засеките время до ответа.
6. Сразу после этого запустите команду ещё раз и сравните время второго ответа с первым.

Запиши для обеих попыток: время ответа, итоговую строку либо полную ошибку. Если первая попытка не завершится в пределах 190 секунд, не повторяй её много раз подряд — пришли время и последние сообщения Python-моста.

## Результат проверки остановки и восстановления моста

2026-10-21 автор остановил Python-мост и выполнил `tolic_ai_test_decision` в консоли сервера:

```text
[Tolic AI] Sending a diagnostic observation to the neural model...
[Tolic AI] Neural decision test failed: HTTP request failed: Couldn't connect to server
```

После повторного запуска Python-моста автор выполнил обе команды:

```text
[Tolic AI] Checking local AI bridge...
[Tolic AI] Bridge replied. Ollama reachable: true; configured model available: true; model: qwen2.5:3b
[Tolic AI] Sending a diagnostic observation to the neural model...
[Tolic AI] Model: qwen2.5:3b; intent: move_to_safety; risk: low; confidence: 0.9; summary: Move to safety due to low risk environment and no recent danger.
```

Мост восстановился без перезапуска игрового сервера. Ошибка подключения была показана явно, а повторная диагностика снова получила ответ настоящей модели. Это закрывает ручную проверку обычного отказа и восстановления моста.

## Ручная проверка недоступного Python-моста

1. Убедитесь, что выделенный сервер Garry's Mod запущен и подключение работает.
2. В окне Python-моста нажмите `Ctrl+C`, чтобы остановить только мост. Ollama и Garry's Mod пока не закрывайте.
3. В консоли выделенного сервера выполните `tolic_ai_test_decision`.
4. Ожидается диагностическое сообщение вида `Neural decision test failed: HTTP request failed: ...`. Точная причина может отличаться. Сервер Garry's Mod не должен зависнуть или аварийно завершиться.
5. Запустите Python-мост снова командой из предыдущего раздела и выполните `tolic_ai_bridge_status`, затем `tolic_ai_test_decision`. Канал должен восстановиться без перезапуска Garry's Mod.

Пришлите фактическое сообщение из пункта 4 и результат после восстановления. Не оставляйте мост остановленным после проверки.

## Проверка жизненного цикла в Garry's Mod

1. Обновите `main` и перезапустите выделенный сервер, чтобы Lua-изменения загрузились.
2. Через Spawn Menu → Entities → Tolic AI создай **Adaptive NPC (Prototype)**. В серверной консоли должно появиться `Prototype NPC spawned`.
3. Создай второй экземпляр. В мире должен остаться только первый, а серверная консоль должна показать `Duplicate spawn rejected; active NPC entity #...`.
4. Удали оставшегося NPC обычным инструментом удаления. В серверной консоли должно появиться `Active NPC removed; registry cleared.`.
5. Снова создай один экземпляр. Должно появиться сообщение о создании, а NPC должен остаться в мире.
6. Смену карты и смерть/удаление NPC проверяй отдельно после успешного выполнения шагов 2–5.

Запиши, какие именно сообщения появились, и подтвердить ли удалось создать NPC повторно после удаления. Само наличие сообщений в коде ещё не доказывает, что игровой цикл работает корректно.

## Что ещё не проверено

Диагностическая команда уже запускалась и вернула ответ модели, однако жизненный цикл NPC (создание/удаление/смерть/повторное создание), вывод Spawn Menu, исполнение игровых действий, поведение при сбое моста и производительность остаются непроверенными.
