# Tolic AI

Экспериментальный аддон для Garry's Mod: NPC с настоящим нейросетевым модулем принятия решений.

> **Статус:** кодовый цикл этапа 3 подключён в отдельной ветке: NPC асинхронно получает решение модели и может выполнить ограниченное сближение с игроком. Это экспериментальная реализация; полноценная проверка в Garry's Mod ещё обязательна.

## Границы разработки

Проект разделён на два крупных блока. Сейчас разрабатывается только **Блок I — основа NPC**. Блок II (команды игрока) не входит в текущую реализацию и не будет разрабатываться до отдельного разрешения автора.

Основа включает:
- одного уникального NPC;
- восприятие игрового мира и получение актуального состояния;
- выбор намерений настоящей нейросетью, а не только набором `if/else`;
- исполнение решений игровым кодом;
- самосохранение, страх боли и смерти;
- отношение к игроку как к наставнику, командиру и существу, которое может возвращаться после смерти;
- адаптацию к мирной и боевой обстановке;
- долговременное обучение и память, переживающую возрождение, без памяти о собственной смерти.

## Архитектура

Нейросеть выбирает высокоуровневое намерение на основе структурированного наблюдения. Lua-код Garry's Mod отвечает за сбор игровых данных, навигацию, физику, разрешённые действия и проверку результата. Ответ модели проходит валидацию и никогда не исполняется как код.

Первый адаптер вызывает локальную модель через Ollama API. Python-мост использует только стандартную библиотеку Python. Его HTTP-сервер по умолчанию привязан к `127.0.0.1`; не публикуйте его в интернет. В многопользовательском режиме сервис должен работать на машине игрового сервера.

## Быстрый запуск прототипа

1. Установите Python 3.10 или новее и Ollama.
2. Загрузите модель в Ollama, например: `ollama pull qwen2.5:3b`.
3. В корне репозитория запустите `python ai_service/server.py`.
4. Скопируйте содержимое папки репозитория в `garrysmod/addons/tolic_ai/` (или создайте там папку и поместите в неё файлы репозитория).
5. Запустите Garry's Mod. В серверной консоли выполните `tolic_ai_bridge_status`, затем `tolic_ai_test_decision`.
6. Для проверки сущности откройте Spawn Menu → Entities → Tolic AI → **Adaptive NPC (Prototype)**.

В Windows, если команда `python` не найдена, используйте установленный исполняемый файл Python или команду запуска, принятую в вашей системе.

### Что должно произойти

- `tolic_ai_bridge_status` показывает доступность AI-моста, Ollama и настроенной модели.
- `tolic_ai_test_decision` отправляет тестовое наблюдение и выводит выбранное моделью намерение.
- `tolic_ai_brain_status` показывает состояние автономного цикла: запрос, последнее намерение и результат исполнения.
- NPC запрашивает решения асинхронно. `observe` оставляет его на месте; `stay_near_player`, `follow_player` и `assist_player` могут привести к ограниченному сближению с ближайшим живым игроком. `move_to_safety` пока безопасно пропускается, поскольку отдельный подтверждённый алгоритм поиска безопасного места ещё не реализован.

Настроить URL моста и здоровье NPC можно в `lua/tolic_ai/sh_config.lua`. Имя модели задаётся переменной окружения `TOLIC_OLLAMA_MODEL`; по умолчанию используется `qwen2.5:3b`.

## Проверки

Из папки репозитория запустите модульные тесты AI-моста:

```sh
python -m unittest discover -s tests -v
```
